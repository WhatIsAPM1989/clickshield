# Безопасность

## Сообщение об уязвимости

Не публикуйте уязвимости, пароли, токены, дампы и приватные записи в Issues.
Используйте [приватное сообщение об уязвимости на GitHub](https://github.com/lamooof/clickshield/security/advisories/new),
если форма доступна. Если приватный канал не включён, создайте Issue только с
просьбой предоставить контакт для безопасной передачи; детали отправьте после
согласования канала. Укажите затронутый коммит, условия и минимальное воспроизведение.
Фиксированного SLA и поддержки старых релизов пока нет.

## Требования эксплуатации

1. Используйте HTTPS и `COOKIE_SECURE=true`, отдельные случайные пароли/токены и закрытый файл окружения.
2. Не публикуйте PostgreSQL и прямой порт приложения в интернет; production Compose привязывает приложение к loopback.
3. `TRUST_PROXY_HEADERS=true` требует proxy, очищающего клиентские forwarding/GeoIP-заголовки. Production Compose включает доверие принудительно.
4. Ограничьте административный доступ VPN, IP allowlist или шлюзом доступа; публичные tracker endpoints должны работать для сайтов проекта.
5. Указывайте точные origins каждого проекта. Публичный project key не является секретом и не заменяет авторизацию.
6. API-токены, `OUTCOME_API_TOKEN` и OAuth/Measurement Protocol secrets храните только на сервере.
7. Ограничьте сроки хранения, явно исключите чувствительные DOM-блоки и не передавайте контакты в бизнес-событиях.
8. Шифруйте резервные копии, храните ключ шифрования отдельно и проверяйте восстановление.

## Секреты и ротация

- Секреты интеграций хранятся в PostgreSQL с AES-256-GCM; `ENCRYPTION_KEY` — 32 байта (рекомендуется base64 от `openssl rand -base64 32`).
- Пароли администратора хешируются bcrypt. Admin session tokens случайные, в БД хранятся их HMAC-SHA-256-хеши с `SESSION_SECRET`.
- API-токены ограничены правами (scopes) и одним или всеми проектами; хранятся SHA-256-хеши, поддерживаются срок действия и отзыв, токен отключённого пользователя не работает. Пользователи, приглашения и токены управляются только из панели. MCP вызывает те же маршруты с теми же проверками.
- Смена `SESSION_SECRET` делает старые admin-сессии недействительными. Простая замена `ENCRYPTION_KEY` делает существующие секреты интеграций нечитаемыми; сначала подготовьте перенос/повторный ввод. Автоматической ротации ключа шифрования нет.
- `.gitignore` и `.dockerignore` исключают локальные секреты и дампы; они не удаляют секреты, уже попавшие в историю Git или опубликованные образы.
