# Внесение изменений

Перед началом прочитайте [README](README.md) и [руководство разработчика](docs/development.md).
Об ошибках и предложениях сообщайте через GitHub Issues. Уязвимости — по
[SECURITY.md](SECURITY.md), без публикации секретов и приватных записей.

## Подготовка изменения

1. Создайте ветку от актуальной основной ветки и сформулируйте проблему.
2. Внесите связанное изменение; не включайте случайное форматирование и локальные артефакты.
3. При изменении поведения добавьте подходящую проверку. При изменении API обновите `docs/openapi.yaml`, SDK/типы и затронутые руководства.
4. Для изменения схемы добавьте следующую SQL-миграцию в `internal/store/migrations/`; уже применённые миграции не переписывайте.
5. Выполните `make check`, `make build` и тесты с отдельной PostgreSQL. Для frontend проверьте затронутый сценарий в браузере.
6. В PR опишите проблему, итоговое поведение, выполненные проверки и особенности обновления/отката.

Документация пользователя ведётся на русском, API-имена и код — в принятом
в проекте стиле. Формат Go задаёт gofmt; настройки текстовых файлов — `.editorconfig`.
Коммиты делайте небольшими, с названием, описывающим результат изменения.

Не включайте `.env`, приватные ключи, production-дампы, GeoIP-базы и данные
пользователей. Локальные deploy-скрипты игнорируются; переносимый процесс
развёртывания описан в [operations.md](docs/operations.md).
