# Интеграции с рекламной аналитикой

[Документация](README.md) · [Репозиторий](../README.md)

## Интеграция с Яндекс Метрикой

В Метрике создайте Measurement Protocol token и цели с идентификаторами:

```text
antifraud_bot
antifraud_human
```

В панели проекта укажите:

- `Counter ID`;
- `Measurement Protocol token`;
- включите интеграцию.

Сервис отправляет server-side событие по Yandex ClientID с полями `risk_score`, `classification`, `session_id` и кодами причин. Токен хранится только в зашифрованном виде на backend.

Официальная документация: <https://yandex.ru/dev/metrika/ru/data-import/measurement-protocol>

## Интеграция с VK Рекламой

Поддерживается актуальный пиксель VK Рекламы (Top.Mail.Ru), а не старый `VK-RTRG` из кабинета ВКонтакте. Используется официальный server-to-server протокол офлайн-событий по рекламному идентификатору `rb_clickid`:

<https://ads.vk.ru/help/general/sites/offline_events>

1. Создайте пиксель в VK Рекламе и установите его базовый код на сайт по инструкции кабинета. ClickShield не устанавливает базовый пиксель автоматически.
2. В настройках пикселя создайте три **JS-события** с точными именами `antifraud_bot`, `antifraud_human` и `antifraud_test`. Выберите подходящую категорию пользовательского события; не отмечайте обнаружение бота как покупку или заявку.
3. В панели ClickShield → Проекты → **VK Реклама** укажите числовой ID пикселя и включите интеграцию. Токен не требуется. API: `PUT /v1/projects/{id}/integrations/vk` с телом `{"enabled":true,"pixel_id":"3229418"}`.
4. Для автоматической отправки выберите режим проекта, отличный от `MONITORING`. Этот режим только собирает и классифицирует визиты; тестовая отправка доступна отдельно.
5. Откройте сайт по рекламной ссылке с `rb_clickid`. Tracker сохраняет последний идентификатор в текущей сессии вкладки и передаёт его в API. Новый клик заменяет предыдущий, переходы по страницам сохраняют идентификатор; новая сессия после 30 минут неактивности начинает сбор заново.
6. Укажите ID этой сессии в поле тестирования и нажмите **Тест VK**: отправится настоящее событие `antifraud_test`. Проверьте его в кабинете VK.

После классификации очередь отправляет `antifraud_bot` / `antifraud_human` запросом `GET https://top-fwz1.mail.ru/tracker?id=PIXELID;e=RG%3A/EVENT;rb_clickid=CLICKID`. Стоимость события не задаётся. Score, причины и session ID остаются в ClickShield: этот документированный протокол их не передаёт. Без `rb_clickid` результат доставки — `SKIPPED`; UTM-метка не заменяет рекламный идентификатор. Ошибки сети, HTTP 429 и 5xx повторяются существующей очередью. HTTP 2xx означает успешный HTTP-запрос, но не подтверждает настройку события или атрибуцию в кабинете. Протокол не предоставляет ключ дедупликации, поэтому повтор после потери ответа может дать дубль.

`rb_clickid` также отображается в карточке сессии, CSV и учитывается как признак платного трафика. Для удобства отчётов рекомендуется дополнительно `utm_source=vk`. Аудитории и их исключения настраиваются в VK Рекламе отдельно; интеграция не изменяет рекламные кампании и не блокирует IP в кабинете.

## Интеграция с Google Analytics 4

В GA4 откройте поток данных и создайте **Measurement Protocol API secret**. В панели проекта укажите:

- `Measurement ID`, например `G-XXXXXXXXXX`;
- `API secret`;
- включите интеграцию.

Сервис отправляет `antifraud_bot` / `antifraud_human` с браузерным `client_id`, risk score, classification, session ID и причинами. Measurement Protocol может вернуть HTTP 2xx даже для части семантически некорректных параметров, поэтому после настройки обязательно проверьте события через GA4 DebugView/validation endpoint. В GA4 рекомендуется:

1. зарегистрировать нужные custom dimensions/metrics;
2. создать аудиторию по событию `antifraud_bot`;
3. после ручной проверки связать аудиторию с Google Ads и применить исключение.

Официальная документация: <https://developers.google.com/analytics/devguides/collection/protocol/ga4/sending-events>

## Результаты заявок и контроль качества

Сервер сайта после сохранения заявки отправляет `POST /v1/outcomes` с заголовком
`Authorization: Bearer OUTCOME_API_TOKEN` и полями `session_id`, `external_id`
(ID заявки) и `status: "SUBMITTED"`. Телефон и имя в ClickShield не передаются.
В карточке сессии можно отметить заявку как «Качественная», «Спам» или
«Не состоялась». Отчёт показывает ошибки автоматических правил по устройству
и источнику трафика; ручная классификация не подменяет исходную оценку.

Серверный приём исхода заявки не блокирует её отправку. Если браузер не успел
создать сессию, заявка сохраняется обычным образом.
